Selective Undo via Vector Clock Inversion in Conflict-Free Replicated Data Types (CRDTs)

Domain: Distributed Systems & Concurrency • Artifact: parallel-crdt (VS Code Extension) • Protocol: Yjs Binary State Vectors
The Collaborative Undo Dilemma: In a single-user editor, undo is trivial: pop the top action from a linear stack and revert its character delta. In a distributed multi-user editor with peer-to-peer WebSocket synchronization, a local user's Ctrl+Z must invert only their own past operations, while strictly preserving interleaved concurrent edits introduced by remote peers.

1. The Breakdown of Linear Undo in Distributed Buffers

In centralized or single-threaded text editors, editing operations are recorded as absolute offset shifts:

Action: Delete 5 characters at offset 14. Inverse: Insert the deleted 5 characters at offset 14.

Consider two concurrent collaborators, Alice (Client 1) and Bob (Client 2), operating on a shared document with initial text "The brown fox":

  1. At t1, Alice types "quick " at index 4 → "The quick brown fox".
  2. At t2, before receiving Alice's update, Bob types "lazy " at index 10 → intended to precede "fox".
  3. Both peers synchronize over WebSockets and converge cleanly via CRDT ordering.
  4. At t3, Alice presses Ctrl+Z.

If Alice's client simply deletes 6 characters starting at absolute index 4, but Bob's concurrent insertions shifted the document structure, Alice's naive undo either deletes Bob's keystrokes or splices characters at an invalid offset.

2. CRDT Foundations: Identifiers over Index Offsets

In state-based sequence CRDTs (such as Yjs, Fugue, or RGA), characters are never addressed by volatile integer array indices. Instead, each character item is assigned an immutable global identifier:

ID = (ClientID, LamportClock)

Every inserted character forms a node in an internal double-linked tree. An insertion references the ID of its preceding left neighbor (origin) and right neighbor (rightOrigin). Deleting a character does not remove its node from memory; instead, it marks the node with a tombstone bit (deleted = true) to preserve the causal coordinate plane for concurrent peers.

3. The Architecture of Selective Undo

To implement selective local undo, the editor maintains a client-scoped undo manager that tracks a stack of undo items containing sets of item IDs created or deleted by the local user within a transaction scope.

[Local Mutation Event] │ ▼ [Capture Transaction Scope] ──> Filter operations where item.id.client == localClient │ ▼ [Push to UndoStack] ──────────> Store RelativePositions (Immutable ID pointers) │ ▼ (User presses Ctrl+Z) [Pop UndoStack] ──────────────> Generate Inverse Mutation as a NEW Forward Op

4. Transforming Inverse Operations into Forward Events

A foundational theorem in distributed CRDT theory states that an undo operation must never alter past history. Rolling back the Lamport clock or modifying past state vectors breaks eventual consistency across peers.

Instead, an undo operation is mathematically applied as a new forward mutation with a new incremented vector clock tick:

  • Undoing an Insertion: If Alice previously inserted item (Client 1, Clock 42), undoing it generates a forward delete operation targeting the tombstone state of (Client 1, Clock 42).
  • Undoing a Deletion: If Alice previously deleted item (Client 2, Clock 18), undoing it does not unmark the tombstone. Instead, it re-inserts a duplicate character with reference to the original origin, but with a brand-new ID: (Client 1, Clock 95).

5. Concurrency Verification & Edge Cases

In our implementation of parallel-crdt for Visual Studio Code, we verified the following edge cases:

  • Interleaved Insertions: Alice and Bob type simultaneously within the same word. Alice undoes her edits; Bob's characters remain in place with zero corruption.
  • Remote Deletion of Local Insertions: Alice inserts text; Bob deletes Alice's text. Alice presses undo. Because Bob explicitly deleted the text after Alice's insertion, the undo manager respects Bob's causal intention and does not resurrect the deleted node.
  • Selective Redo: Redoing an undone operation pushes the state forward again using symmetrical inversion.

6. Conclusion & Code Access

By decoupling physical document indices from causal item coordinates and modeling inverse mutations as forward-propagating vector clock events, selective undo achieves mathematical convergence across distributed clients with zero server-side lock coordination.

The complete implementation, including WebSocket signaling and VS Code language buffer bindings, is available in the parallel-crdt repository.
