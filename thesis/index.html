Migrating Spring Boot MVC Systems to Java 21 Virtual Threads: Architecture, Risks, and Engineering Guidelines

Author: Mohamed Hamed • Institution: Eötvös Loránd University (ELTE) • Degree: M.Sc. in progress
This thesis uses controlled Spring Boot workloads to separate carrier pinning from application-level contention. The documented benchmark environment is an Apple M1 with 8 GB of memory running macOS (arm64). Run manifests record the runtime and tool versions for each workload.

1. Java 21 lock comparison

On October 15, 2026, six runs compared synchronized with ReentrantLock on the synthetic /payments endpoint, with three runs per treatment. Java 21.0.8 ran with one carrier and 10 closed-loop k6 virtual users. Both locks protected the same 500 ms operation.

Lock Steady throughput Mean steady p50 JFR pin events per run
synchronized 1.967 req/s 4,966.8 ms 108
ReentrantLock 1.956 req/s 4,982.0 ms 0

Changing the lock freed the carrier during blocking in this workload. The shared lock still serialized requests, leaving a capacity bound near 2 req/s.

2. Evidence by experimental stratum

The repository census covers 125 physical executions across eight strata. The normalized evidence explorer has 76 records. The census also includes 27 exploratory runs and 13 excluded or construct-flawed runs. A separate schema template is metadata.

  • Java 21 synchronization (stratum 1). The 12-run matrix includes the six lock-treatment runs above and platform-thread and no-lock controls. The no-lock control drops the mutual-exclusion invariant.
  • Runtime evolution (stratum 2). In the six Java 24 lock-comparison runs, both treatments averaged 1.967 req/s with zero recorded monitor pins.
  • Native boundaries and endpoint controls (strata 3 and 4). Separate JNI and endpoint diagnostics test native carrier capture and other sources of contention.
  • Historical baseline (stratum 5). The October 8 eight-carrier baseline is a distinct run set. It recorded 110 pins per synchronized run.
  • Persistence ablation (stratum 8). In six Java 21 runs with 50 virtual users, embedded H2 and a 300 ms connection hold, pool sizes 1 and 10 yielded 3.27 and 32.60 steady req/s respectively, with zero recorded pins in both treatments.
